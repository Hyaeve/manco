# Manco v0.6.8 发布总结

## 阶段目标

本版本集中完成下载通知闭环、系统设置页重构、SQLite 查询性能优化、订阅封面持久索引，以及信息总览视觉与交互升级。

## 下载通知

- 新建订阅并选择下载历史章节时，会持久记录一次完成通知任务。
- 当该批次不再有排队、下载中、暂停或自动重试任务后，统一发送一条 Telegram 汇总通知。
- 汇总通知包含作品封面、名称、作者、简介、成功章节数、失败章节数和下次检查时间。
- 通知状态写入数据库，容器重启后继续等待，不会因为进程中断而丢失。
- 容器重启后，重新入队的下载任务会发送“Manco 已恢复任务下载”通知，列出作品和章节；超过 20 条时自动汇总。
- 普通排队任务不会被误判为重启恢复任务。

## 系统设置

- 设置页重构为“连接与安全”“下载与通知”“维护与版本”三段布局。
- 账号、代理、下载设置、TG 通知、日志、归档繁转简和关于窗口统一为等高双列或三列表单。
- 保存按钮固定在卡片标题区域，日光主题使用侧栏选中色，夜间主题使用对应的暖色样式。
- 保留回车保存、自动保存和原有设置锚点，侧栏账号菜单跳转继续有效。

## SQLite 性能

- 订阅清单的来源类型、下载目录、执行时间/添加时间/标题排序、升降序和分页全部下推到 SQLite。
- API 只返回当前页订阅，不再先加载全部订阅后在 Go 中筛选、排序和切片。
- 卡片成功、失败、等待统计只聚合当前页作品，不再每轮轮询扫描全部下载历史。
- 首页统计由 7 次查询合并为一次聚合查询。
- SQLite 使用单写入连接和 3 个只读连接，保留 WAL，增加 `synchronous=NORMAL`、8 MB 缓存、`temp_store=MEMORY` 和 `PRAGMA optimize`。
- 增加订阅活跃、归档、执行时间、标题、目录、完成任务排序和失败重试到期索引。
- 作品详情页新增精确订阅匹配接口，不再为判断是否订阅而读取全部订阅。
- 本地封面缓存增加目录签名和未命中缓存，目录变化时自动失效。
- 调度器检查成功后按扫描周期刷新 `subscriptions.json` 快照，不再由页面 GET 请求触发全量写盘。

## 订阅封面索引

- 新增 `/data/subscription-covers/index.json` 和 `covers/` 独立持久目录。
- 索引以 `sourceId + comicId` 为键，记录作品名称、封面文件、封面模糊状态、来源封面和更新时间。
- 封面读取顺序统一为：下载目录封面、订阅封面索引、发现缓存、来源远程封面。
- 已下载作品的 `cover.*` 会自动复制到订阅封面索引。
- 发现缓存中已存在的封面会复制到独立索引，不依赖发现缓存 30 天保留期。
- 订阅计划加载时会异步通过来源图片运行时或 HTTP 物化缺失封面，后续直接读取本地文件。
- 新增 `/api/subscription-cover` 读取索引封面。
- 本地仓库返回 `coverBlur`，信息总览轮播和订阅计划小封面会应用模糊效果，鼠标悬浮时临时清晰，移出后恢复。

## 信息总览

- 左上角轮播移除“最近下载”文字，增加作品 Tag 胶囊。
- 背景改为双层交叉淡入，内容从右侧轻微浮入，自动切换更自然。
- 轮播圆点支持鼠标悬浮切换；白色圆点通过弹性宽度动画展开为白条。
- 统计总览、资源拓展、下载队列、订阅计划统一为单层小标题和线条图标。
- 统计图标放大，并调整卡片左侧留白。
- 内容源图标固定为 30px，名称位于图标下方，点击进入对应探索发现页。
- 下载队列增加页级进度条，排队和等待任务也显示进度轨道。
- 订阅计划只显示作品名称、作者和“今天/明天/后天/周几/下周几 HH:mm”的相对执行时间。
- 下载队列和订阅计划标题及条目可直接进入对应页面。
- 侧栏“订阅清单”页面名称调整为“订阅计划”。

## 已知限制

- 远程订阅封面采用恢复期后台物化；第一次打开订阅计划时，如果本地和发现缓存都没有封面，可能先显示远程回退图，后续加载使用本地索引。
- 删除订阅后，`data/subscription-covers` 中已生成的旧封面文件暂不自动回收。
- 插件封面仍受所属插件运行时可用性影响；运行时不可用时回退到普通 HTTP 封面或来源远程地址。
