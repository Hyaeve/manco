# Manco v0.5.1 发布总结

## 阶段目标

- 降低探索发现页首次加载、搜索和切换来源时的内存与磁盘压力。
- 完善订阅清单、归档集和资源拓展的多选、排序与目录同步操作。
- 修复书籍源详情可显示但章节列表为空的问题。
- 完成全量构建测试后，以中文提交信息、发布说明和标签推送 `v0.5.1`。

## 实际改动

### 探索发现缓存与加载

- 发现缓存启动或首次访问时建立一次 `source + kind + comic` 内存索引，不再反复全量扫描目录。
- 浏览和搜索结果只持久化轻量卡片信息，不再同步下载插件封面或生成 `ComicInfo.xml`，详情访问仍保留完整缓存。
- 访问时间改为有间隔的异步写回，避免频繁磁盘写入阻塞页面请求。
- 发现网格优先使用本地缓存封面，减少重复远程图片代理请求。
- 后续卡片刷新会合并已有详情元数据，避免轻量列表刷新覆盖已缓存的作者、简介、标签和章节数。

### 订阅、归档与资源拓展

- 订阅清单在来源类型栏目下新增目录筛选胶囊行，可按下载位置末级目录过滤。
- 订阅卡片和归档卡片支持右键进入多选、左键切换选中和 Shift 连选，页面底部显示统一操作胶囊条。
- 订阅批量操作支持检查、全量、补全、归档和删除；删除与归档等操作继续使用二次确认。
- 归档集批量操作支持移出归档，返回订阅清单。
- 资源拓展中的内置源保持固定，插件源可在同类型内拖动排序并始终排在内置源之后；探索发现同步按该顺序展示内容源。
- 修改订阅作品目录或下载位置时，同步迁移本地作品文件夹，并更新下载任务记录的目录和文件路径。
- 从拓展仓库添加内容源时，网站图标同步缓存到本地 `/data/icon`。

### 书籍章节

- 新增详情与章节合并获取接口，插件源和书籍源可在一次上游操作里返回作品详情与章节列表。
- Z-Library 复用同一份详情响应生成电子书章节，不再为章节额外请求一次 EAPI。
- API 缓存补齐、详情接口、章节接口和后台刷新统一走合并链路；章节加载失败会返回明确错误，不再静默伪装成空章节。
- 增加 API、Kototoro/Mihon 插件适配器和 Z-Library 单请求回归测试。

## 已知问题

- 首次建立发现缓存索引时会读取现有缓存目录；后续启动和页面访问复用内存索引。
- 书籍源必须在上游详情中返回可下载章节；来源本身声明无可下载文件时，页面不会伪造章节。
- Mihon / Aniyomi APK 的运行能力仍取决于镜像内兼容运行时，仅登记清单的仓库不会因此自动获得执行能力。
