# Manco v0.7.3 发布总结

## 阶段目标

本次为常规版本，汇总 `v0.7.2` 后尚未发布的变更。主要降低大量排队任务、插件清单加载、本地仓库和章节列表带来的内存与界面开销，并修复插件视频被送入图片处理链路而下载失败的问题。

遵循先推送代码及标签、再补发布总结的交付顺序。正式版本号为 `v0.7.3`，不移动已有标签。

## 实际改动

### 插件视频下载

- 新增统一媒体解析能力，由插件运行时解析资源地址、请求头和 Cookie。
- 视频不再进入仅接受图片签名、最大 64 MiB 的图片缓存。
- MP4 等原生文件流式落盘，不整段读入 Go 内存，保持来源文件格式。
- HLS / DASH 分段流使用 FFmpeg 无转码封装 MKV；镜像增加 FFmpeg。
- 分段下载沿用内容源的代理策略，保留 Referer、User-Agent 和 Cookie，避免被旧账号 Cookie 覆盖。
- 使用临时文件与原子发布；取消或失败不留下最终半成品。
- FFmpeg 输出不写入日志，避免签名资源地址和凭据泄漏。

### 后台性能

- 读取插件清单时仅枚举来源，不再构造并保留全部解析器；实际使用某个来源时才创建。
- 添加单个插件源时按需读取其域名，继续支持本地图标获取。
- 插件详情保留传入作品 ID，不把完整章节目录反复编码进作品 ID。
- 稳定 ID 下仍使用最新详情中的封面地址，避免回退到列表中的旧封面。
- 图片及媒体逐页下载采用固定数量的工作协程，结果缓冲也随并发数限制。
- 下载详情共享缓存限制为 64 项；全局并发已满时不再额外扫描排队任务。
- 修复同一章节完成后被重复计入来源批量暂停的问题。

### 任务列表

- 首批 100 条，继续随滚动分页，保留虚拟行渲染。
- 筛选和搜索改由 SQLite 执行，不再只筛已加载的首批任务。
- 新增活动任务排序索引，保留手动任务优先级。
- 紧凑进度接口不再返回重复简介、标签、章节运行时载荷和合并章节数组，也不扫描本地封面或补读本地元数据。
- 轮询只刷新首批与当前可见的尾部任务，移除已完成或已删除的旧条目。
- 合并重复请求，忽略过期响应；页面切走或标签页隐藏时停止后台轮询。

### 本地仓库

- 新增共用窗口化网格，用于作品网格和章节网格。
- 作品列表仅返回摘要和章节数量；进入作品后才读取该作品的章节目录。
- 章节封面由浏览器懒加载，不再打开作品就逐章请求所有压缩包的完整目录。
- 缩略图生成限制两路并发，并在像素解码前拒绝超大尺寸图片。
- 信息总览的海报列表也改用摘要接口。
- 移除本地仓库“加载更多”按钮，保持随滚动自动加载。
- 修复小屏详情栏和顶栏撑宽问题。

### 此前未发布内容

- 任务列表批量重试改为单次批量接口，同一作品的所选章节统一发送一条 TG 重试通知。
- 移除探索发现卡通猫加载动画，保留骨架占位和普通加载状态。
- 网页和 TG 共用服务端持久化的最近五次全局搜索，包含漫画、书籍和视频类型搜索；指定单源搜索不写入该历史。
- 搜索关键词规范空白、不区分大小写去重，最新搜索置顶。
- 修复历史读取时顺序反转、顶栏残留旧 localStorage 历史，以及无可选源时的匹配越界。
