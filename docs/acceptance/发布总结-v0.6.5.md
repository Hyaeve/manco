# Manco v0.6.5 发布总结

## 阶段目标

完成 TG 搜索结果详情提速、详情章节数量与简介清理、订阅清单新状态格式，以及 `/check` 全量订阅检查指令。本总结同时合并 `v0.6.4.1` 与 `v0.6.4.2` 两个小版本，二者不单独建立验收文档。

## 实际改动

### TG 搜索结果与详情

- 点击搜索结果后先使用列表缓存立即发送详情卡片，不再等待内容源详情请求。
- 后台拉取作者、最新章节、简介和完整章节数量，成功后原位编辑同一条消息。
- 封面加载增加 5 秒超时，超时回退为文字详情，避免图片来源拖住整个交互。
- 回调应答、旧消息删除和新消息发送改为并行，减少点击按钮后的串行 API 等待。
- 返回搜索结果时直接复用已缓存的列表文本，不再重新组装列表。
- 详情新增“章节数量：共 N 章”；连载中作品同样显示统计。
- 简介会清理 HTML 与“《作品名》最新章节,《作品名》全集,”等来源摘要前缀，只保留正文。

### 订阅清单与 `/check`

- `/subscriptions` 改为“序号. 作品名（内容源简写）🟢/⚪”。
- 中文内容源名称取前两个汉字，英文名称取前四位；绿色圆点表示启用，灰色圆点表示停用。
- 新增 `/check` 并注册到 TG 命令菜单，并发检查订阅清单中的全部卡片。
- `/check` 复用同一条消息展示汇总，包括成功、失败、新章节、实际入队、失败重试和单项错误。
- 调度器新增 `CheckOneDetailed`，让单作品检查和 `/check` 都能获得可靠的新章节与入队数量。

### 合并的小版本 v0.6.4.1 / v0.6.4.2

- v0.6.4.1 增加订阅总章节数写入，并完成浮出动画、排序控件对齐、保存按钮、侧栏与全站选中态、暖色日光主题和任务列表空白修复等界面调整。
- v0.6.4.2 修复总章节数的完整数据库链路：旧库自动补 `chapter_count`，订阅查询、字段扫描与快照恢复完整贯通，调度器写入失败不再静默。
- 订阅清单和归档集在章节数未知时不再显示无意义的“0 话”。

- 详情首屏依靠搜索缓存。若来源封面在 5 秒内不可用，会先显示文字详情；后台详情请求失败时保留缓存内容。
