# Manco v0.5.6 发布总结

## 阶段目标

- 修复订阅清单重新加载后上下滑动就无响应（浏览器 `RESULT_CODE_HUNG`）。
- 修复禁漫天堂内置源下载的 CBZ 里图片分层错乱。
- 元数据简介去掉 HTML 包裹，让 KMRS / Komga 读出来是纯文本。
- 活动通知、任务列表多选、功能开关按既定视觉与交互规范收敛。
- 项目 logo 换成卡通纸箱猫横条图与圆角图标。

## 实际改动

### 订阅清单无响应（本版主要修复）

上一版为活动通知做聚合时引入了三处开销，叠加后表现为订阅清单必卡死。本版逐项收敛：

1. `/api/activity` 整表扫描
   - 原实现用 `ListDownloadJobs(ctx, 0)` 读**整张** `download_jobs` 表，再在 Go 里分组；前端每 15 秒轮询一次，任何页面都在付这个成本，任务表越大越明显。
   - 现在改为 SQLite 端聚合：新增 `Store.DownloadJobActivity`，用 `GROUP BY source_id, comic_id` + `SUM(CASE…)` + `HAVING 已完成或失败` + `LIMIT 50`，开销只跟作品数相关。
   - 纯排队的作品不进通知，已完成 / 失败作品仍带 `pending` 计数。
   - 新增 `parseSQLiteTime` 兼容多种 SQLite 文本时间戳格式。
2. 卡片级全表扫描
   - 订阅卡片模板里 `jobStats()` 原来对每个卡片各做两次 `jobs.filter(...)`，即「卡片数 × 任务数」。
   - 现在预聚合成 `statsByComic` Map，模板只做 O(1) 查表。
3. 渲染与解码
   - 订阅卡片改为分批渲染（首屏 60 张，滚动接近底部时追加 60 张），切换筛选时重置批次。
   - 5 秒静默轮询在订阅内容 / 统计 / 任务状态未变化时不再替换响应式数据，避免整页重渲染。
   - 订阅、归档、完成列表、探索发现列表与本地仓库的封面统一加 `decoding="async"`，把图片解码从主线程移开（此前只有 `loading="lazy"`）。

### 禁漫天堂 CBZ 图片分层错乱

- `scrambleParts` 的分段数判定改用「MD5 末位十六进制字符的 ASCII 值」，阈值 `>= 421926`。
- `scrambleTargetID` 优先使用章节自身的 photo id。
- 对照 `JMComic-Crawler-Python` 的 `JmImageTool.get_num` / `decode_and_save` 验证一致。

### 元数据简介去 HTML

- 新增 `plainMetadataText`（基于 `golang.org/x/net/html`）把来源简介转纯文本。
- `ComicInfo.xml` 的 `Summary`、`series.json` 的简介都写纯文本，不再输出 `<p>…</p>`。
- 新增 `hasHTMLTag` / `metadataDescriptionHasHTML`，让带 HTML 的旧元数据在下次检查时被判为过期并自动重写。

### 活动通知

- 通知窗口改为淡黄底，标题加粗，摘要不再用斜体、不再放大。
- 聚合到「一个作品一条」，只显示成功 / 失败 / 待处理章节数。

### 任务列表与多选

- 任务列表「完成列表」独立成页，标题与返回按钮重做（图标 + 文字）。
- 多选操作条顺序统一为「已选 / 全选 / 清除 / 重试 / 删除」，删除会带二次确认并连同已下载文件一起删除。
- 订阅清单、归档集右键进入多选，Shift 连选；切走页面自动退出多选。

### 功能开关与视觉

- 订阅 / 下载任务设置里的功能项统一成图标 + 文字圆角按钮，启用时高亮、未启用置灰。
- 探索发现筛选栏收敛为单行、放不下横向滚动，网格 / 列表切换按钮移到搜索栏右侧且不再套圆角框。

### 项目 logo

- 侧栏品牌区改为横条图 `brand-lockup.png`（浅色）/ `brand-lockup-plate.png`（深色），移除旧的 SVG 组件式 `MancoLogo` 用法。
- 站点图标换成 `logo-icon.png`，删除 `favicon.svg`。

## 已知问题

- 本版对订阅清单卡死的三处修复都基于代码路径推断：本机没有用户规模的数据（本地 `manco.db` 均小于 200KB），也没有在跑的实例，因此「重载后上下滑动必卡死」的现场未能本地复现。
- 封面仍按源站原图下发，几百个订阅会把几百份大位图交给浏览器解码，内存占用偏高。
- `/api/subscriptions` 每张订阅卡片都会对作品目录做一次 `cover.*` 通配查找，在 NAS 上按订阅数量线性放大。
