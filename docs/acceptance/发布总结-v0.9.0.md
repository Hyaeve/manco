# Manco v0.9.0 发布总结

## 阶段目标

本次为常规版本，承接 v0.8.2。目标是让 Bangumi 作为探索发现页的作品展示栏目接入订阅计划，同时不把 Bangumi 伪装成普通可执行内容源：

- Bangumi 作品加入订阅后，漫画只在漫画源中匹配，小说只在书籍源中匹配。
- 匹配成功时自动切换到最优的真实内容源；匹配失败时保留 Bangumi 待匹配订阅，由后续 cron 检查继续重试。
- 补全登录页 Bangumi 随机海报、内容源筛选持久化、信息总览路由与布局等同期改动。

遵循先推送代码和标签、再补写总结的顺序，不移动已有版本标签。

## 实际改动

### Bangumi 探索与登录展示

- 探索发现页新增首个 Bangumi 栏目，包含近期注目、连载中、本月新作、今年新作、收藏最多、排行榜、高分漫画、高分小说 8 个展示源。
- Bangumi 栏目支持分页、网格和列表展示、右键多选和批量加入订阅，但不出现在普通内容源注册表、内容源管理和可下载源列表中。
- Bangumi 条目点击后打开对应 `https://bgm.tv/subject/<id>` 页面，不进入普通作品详情下载流程。
- Bangumi 封面通过图片代理加载，并加入对应图片域名白名单。
- 登录页背景从上述 8 个分类中混合抽样最多 10 部作品，优先使用高分辨率封面。
- Bangumi 数据和封面接口继续使用系统代理；未配置或请求失败时不展示相关海报。

### Bangumi 智能订阅匹配

- Bangumi 订阅新增来源字段，持久化原始来源、原始作品 ID、原始详情 URL、匹配类型、匹配状态、错误信息和最近尝试时间。
- 漫画类 Bangumi 作品只搜索已启用且可搜索的漫画源；小说类只在书籍源中搜索，不会跨类型匹配。
- 匹配最多同时搜索 3 个内容源，整体超时 45 秒。
- 标题先去空格和标点、统一小写并执行繁转简，再使用完全匹配、包含关系和字符二元组相似度评分；作者重合额外增加权重。
- 匹配阈值为 0.72，超过阈值时选择得分最高的候选；得分相同时保持内容源注册顺序。
- 匹配前会检查候选是否已经被另一条订阅占用，避免同一真实作品生成重复订阅。
- 未找到候选、匹配超时或候选已在订阅计划中时保留原 Bangumi 订阅，并记录 `unmatched`、原因和尝试时间。
- cron 到期检查时先执行匹配；仍为 Bangumi 来源的订阅会再次搜索，匹配成功后再记录章节基线并按正常订阅流程检查。
- 订阅卡片在待匹配、未匹配和匹配错误状态下显示 Bangumi 图标及等待提示；匹配成功后自动切换为真实内容源图标，后续使用真实内容源详情和下载流程。
- 手动添加后先在后台尝试匹配，不阻塞订阅创建响应；订阅列表会在存在待匹配项时轮询刷新。

### 数据与界面

- SQLite 为订阅表自动补齐 Bangumi 匹配字段，兼容已有数据库，无需手工迁移。
- 内容源筛选状态保存到 SQLite 的 `source_browse_filters`，重启服务或更换浏览器后仍可恢复。
- 信息总览页面路由统一为 `/dashboard`，侧栏、登录后跳转和旧地址兼容同步调整。
- 统计条目改为小标题在上、数字在下，收紧条目间距；横幅海报的 Tag 固定单行省略，简介占用剩余空间，按钮与封面底边对齐。

## 已知限制

- Bangumi 栏目依赖外部 Bangumi API 和系统代理；当前环境的外部搜索接口曾出现连接不稳定，真实多源匹配仍需在 NAS 代理环境持续验收。
- Bangumi 漫画/小说类型来自栏目分类；如果条目本身分类异常，首次匹配可能进入错误的搜索类型，但不会跨多个类型做猜测扩展。
- 匹配质量依赖内容源搜索返回的标题和作者。45 秒超时内未返回的内容源不会参与本轮比较，订阅会保留并等待下一次 cron 重试。
- 内容源搜索结果可能存在同名不同作品。当前使用标题相似度、作者重合和阈值保护，仍需要在真实数据中观察误匹配率。
- Bangumi 自身不是可执行下载源，未匹配期间不会产生章节下载任务。

## 下一步

在 NAS 代理环境使用一组漫画、小说和同名作品，验收真实内容源匹配顺序、40 至 60 秒慢搜索、重复订阅拦截以及后续 cron 自动重试；如果出现稳定误匹配，再引入来源 URL、年份或标签作为补充评分条件。
