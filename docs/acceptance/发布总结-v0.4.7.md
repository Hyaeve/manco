# Manco v0.4.7 发布总结

## 阶段目标

- 让 Mihon/Aniyomi 系 APK 拓展仓库可以在容器内登记并实际执行内容源，不再停留在“仅登记清单”。
- 补齐插件源设置、添加内容源筛选和来源图标本地化，修复 Mihon 源偏好保存失败。
- 让下载生成的元数据可被 Komga、Mylar 和 OPF/EPUB 生态读取，并让本地仓库详情页解析这些元数据。
- 优化探索发现、侧栏切换、本地仓库角标和时间排序图标等前端体验。

## 实际改动

### Mihon 运行时与拓展仓库

- 新增 `runtime/mihon-host`，将 Android/JVM APK/DEX 转换为桌面 JVM 可加载的插件，并通过固定版本的 Suwayomi AndroidCompatibility 运行时执行。
- `Dockerfile` 新增 Mihon 运行时生产阶段和独立 host 构建阶段；最终镜像同时携带 Kototoro 与 Mihon 两个 JVM sidecar。
- Mihon 运行时仍从固定 Suwayomi 提交、固定补丁和固定构建时间重建；Linux 容器不会复用 Windows/JDK 25 产物的字节级 SHA-256，因此仅跳过上游面向 Windows 产物的哈希门禁，保留固定源码、补丁和 JAR 集合约束。
- `internal/pluginruntime` 支持按来源选择 Kototoro/Mihon 运行时，分别保存配置、偏好和图片目录，并将 Mihon 的 `sources` 操作映射到统一调用协议。
- 添加内容源不再对 Mihon APK 直接返回不可执行错误，而是进入插件安装、运行时注册和内容源候选流程。
- 插件偏好值统一使用 Mihon 当前协议的 `operation` 字段，修复域名、线路等设置保存时报 `INVALID_REQUEST` 的问题。

### 内容源与图标体验

- 添加内容源窗口固定尺寸并加高，支持按仓库、内容类型筛选候选来源。
- 仓库和类型筛选改为可横向滚动的胶囊/圆角按钮行，空间不够时显示左右翻页按钮，并支持滚轮横向浏览。
- 新增来源候选缓存，切换仓库或类型时复用已加载结果。
- 新增自定义来源图标本地化：优先下载来源图标到 `/data/icon` 并持久化为本地 `/api/icons/{id}`，失败时保留远程图标供类型图标兜底。

### 元数据与本地仓库

- `ComicInfo.xml` 扩展 `Count`、日期、作者分工、`Tags`、`Publisher`、`LanguageISO`、`AgeRating` 等字段，并继续做到一章一个 CBZ。
- 作品目录新增 Mylar/Komga 读取的 `series.json`，以及 OPF/EPUB 读取的 `metadata.opf`；保留 Manco 自身的 `book.json`。
- 订阅检查更新时，如果 `series.json`、`metadata.opf` 或对应章节元数据缺失，会重新补齐元数据。
- 本地仓库详情解析 `series.json`、`metadata.opf`、`ComicInfo.xml` 和 `book.json`，补充状态、出版社、语言和出版日期等信息。
- “本地库”统一改名为“本地仓库”；网格章数角标改为橙色白字，一位数为圆形，多位数为胶囊，并略凸出封面右上角。

### 前端交互与缓存

- 探索发现先渲染来源、筛选和工具栏，再异步加载内容网格，减少进入页面时的空白等待。
- 侧栏主页面使用 `KeepAlive`，在同一个浏览器会话内切换回已加载页面时复用组件和已加载数据，并恢复页面滚动位置。
- 作品详情页章节时间排序改用正序、倒序图片图标。
- 完善添加来源弹窗、内容源卡片和本地仓库相关样式。

## 已知问题

- Mihon/APK 运行时依赖固定的 Suwayomi 兼容运行时和 Kototoro 上游提交，首次镜像构建耗时会明显高于仅构建 Go/Vue 的版本。
- `series.json`、`metadata.opf` 和增强后的 `ComicInfo.xml` 已写入下载目录，但第三方阅读器实际扫描结果仍取决于用户对 Komga/Mylar 元数据读取开关的配置。
- 本机缺少 Docker CLI，镜像构建结果需要以远端 GitHub Actions 为准。
