# Manco v0.9.8 发布总结

## 阶段目标

本次为常规版本，承接 v0.9.7。目标是完善 Bangumi 匹配成功后的 Telegram 通知，让 Bangumi 订阅在未选择自定义目录时跟随匹配内容源默认下载目录，并更新 README 品牌图背景。

遵循先推送代码和标签、再补总结的顺序，不移动已有版本标签。

## 实际改动

### Bangumi 匹配通知

- Bangumi 订阅匹配成功后发送一条持久 Telegram 图片通知。
- 通知包含匹配内容源的封面、作品名称、完整内容源名称、作者、作品状态、原 Bangumi 名称和简介。
- 优先使用匹配内容源详情中的封面和简介；详情不可用时回退搜索结果及原 Bangumi 封面。
- 封面模糊状态沿用订阅卡片设置，通过 Telegram `has_spoiler` 展示。
- 清理简介中常见的“作品讲述”“内容简介”等前缀。

### Bangumi 下载目录跟随

- Bangumi 新订阅的下载路径默认留空，表示跟随匹配内容源默认目录。
- 匹配成功后动态解析实际目录，调度器在定时检查、全量、补全和手动下载入队前重新解析。
- 用户选择自定义下载路径后保持固定，不再跟随内容源默认目录。
- 作品目录名称继续支持独立自定义。
- 订阅接口新增 `followSourceDownloadDir` 和 `effectiveDownloadDir` 展示字段；订阅卡片与编辑窗口可显示和切换跟随状态。

### README 品牌图

- README 顶部品牌图改为带浅橘色 `#FDE5D2` 背景的 `readme-brand-lockup.png`，完整保留猫箱图标与 Manco 字标。

## 已知限制

- 匹配内容源详情接口不可用时，通知会回退到搜索结果的封面和简介；仍无简介时只发送可用字段。
- 内容源默认目录变化只影响后续新入队章节，已经创建并带固定目录的历史任务不会自动迁移。
- Telegram 图片消息仍依赖可访问的封面 URL 或本地缓存封面。
