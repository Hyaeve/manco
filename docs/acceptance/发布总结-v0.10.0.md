# Manco v0.10.0 发布总结

## 阶段目标

本次为常规版本，承接 v0.9.9，按修订位十进制规则进位为 v0.10.0。交付此前只在本地完成的 Z-Library 会话修复与探索发现默认栏目调整，避免用户继续使用不含修复的旧镜像。

遵循先推送代码和版本标签、再补写总结的顺序，不移动历史标签。程序侧错误处理已回归验证，但不将其表述为已经通过 Z-Library 人机验证或完成真实账号下载验收。

## 实际改动

### Z-Library 会话与重定向

- 请求使用按账号凭据隔离的 Cookie Jar，接收并复用防护握手的 `Set-Cookie`，修复没有保存 Cookie 时同地址反复重定向的问题。
- 复制共享 HTTP 客户端，保留既有代理与传输配置，不修改其他内容源使用的客户端。
- 使用用户设置的 User-Agent；修改 Cookie、登录凭据等配置后重置旧的内存防护会话。
- 重定向最多五跳，循环跳转返回浏览器验证提示；拒绝 API 跨站重定向，避免把登录 POST 表单转发至其他域名。
- 文件下载允许正常跨站跳转，但不向文件站点发送源站 Cookie；拒绝不安全的重定向。
- 识别 DiamWall 等浏览器验证页面、HTTP 513、401 登录失效和非 JSON 网页，返回可操作提示，不再向用户输出整段验证 HTML。
- API 的失败响应不再作为空列表成功返回，兼容布尔与数值成功标志。
- 下载时拒绝将验证 HTML 当作 EPUB 等电子书保存，包括以二进制类型返回的验证页面。
- 取消请求后停止继续尝试镜像。
- 移除 `z-lib.io`、`singlelogin.re` 默认回退与对应静态图片白名单；保留用户自定义站点入口。
- Z-Library 编辑窗口新增浏览器 Cookie、User-Agent 和打开网站验证按钮，使用已有账号接口加密保存，没有新增 API。
- README 补充人工验证及同网络或代理出口要求。

### 探索发现默认栏目

- 没有本会话浏览记录时，默认选择 Bangumi 近期注目。
- 成功登录后清理旧的探索发现位置和内存面板缓存；登录返回探索发现时不再沿用旧 `kind/source` 参数。
- 容器重启导致登录会话失效并重新登录后，不会继续恢复旧的内容源栏目。
- 同一会话内仍保留栏目、Bangumi 子栏目、页码和滚动位置，普通页面刷新也保持位置。
- 内容源持久化筛选、排序及网格或列表设置不被此次会话重置清除。
- 新增四项 Node 原生会话测试，并加入现有 GitHub Actions 前端构建步骤。

### 版本

- 应用版本与 README 标签示例统一更新为 `v0.10.0`。
- 内置内容源、章节打包格式及订阅基线规则保持不变。

## 已知限制

- 无账号探测中，保存防护 Cookie 后两个 `.sk` 站点仍可能返回 DiamWall 人工浏览器验证；不会尝试代替用户自动绕过验证。
- 需要时在来源编辑窗口打开网站，在与 Manco 相同网络或代理出口下完成验证，填写该浏览器的请求 Cookie 与 User-Agent 并保存；有效性仍取决于站点的会话和风控策略。
- 尚未使用真实 Z-Library 账号验证登录、浏览与下载；本次发布不保证每个网络出口都能访问该服务。
- 未执行真实容器重启或浏览器端到端验收，默认栏目行为由 Node 测试与构建验证。
- 本机无 gcc，未执行 Go race 检测；本机无 Docker CLI，镜像构建由 GitHub Actions 执行。
- 本次不接入快看、腾讯动漫或哔哩哔哩漫画，之前对此的讨论不属于已实现功能。
