# Manco v0.6.0 发布总结

## 阶段目标

- 让「每 N 章暂停 M 分钟」真正生效，并统一下载并发上限与默认值。
- TG 搜索→详情→返回→订阅 改成「同时只留一个消息框」，详情补齐作者/简介/最新章节。
- 探索发现列表的作者/简介/连载状态回填，详情页补最后更新日期。
- 本地仓库分页加载；订阅卡片排版、状态显示与排序调整。

## 实际改动

### 下载引擎

- **批量暂停从空转变真**：新增 `Engine.markCompleted`（标记完成后计数）与 `noteBatchCompletion`（全局计数**跨所有内容源累加**，达到 `batchSize` 就把 `cooldownUntil` 设为 now+M 分钟并清零；每源计数同理）。5 处 `UpdateDownloadJob(..., "completed", ...)` 落点全部改走 `markCompleted`——此前这两个计数器从未被赋值，功能完全空转。
- `inCooldown` **先判全局冷却**再判每源冷却；新增 `GlobalCooldown()`，`handleListDownloads` 用它把全局暂停期间排队中的章节标成「等待中」；暂停结束时用一次性 goroutine 主动 `Notify()`，不等 20 秒轮询。
- 默认值：每下载 **30 章**暂停 **5 分钟**。
- 并发上限：章节/图片均放宽到 **1–32**（抽成 `maxChapterConcurrencyLimit` / `maxPageConcurrencyLimit`，后端校验、每源解析、设置页与资源拓展输入框全部对齐）。此前默认 10 会被 1–8 的旧校验挡住。

### TG

- **消息框切换**：会话新增 `detailMessageID`。点候选→先删搜索结果再发详情（`sendPhoto`，失败退回文本）；点返回→删详情并**重发**搜索结果供重选；点订阅→删详情、回复结果、清会话。
- **详情补齐**：新增 `BotComicDetail`，走和网页端同一条 `loadComicDetail` 链路，补齐作者、简介、最新章节（取不到则退回列表里的信息）。
- 中文指令 `启用/禁用 作品名`；`setMyCommands` 注册 `/start`、`/subscriptions`、`/sources`、`/s`，描述精简为「查看订阅清单」「搜索作品」。订阅列表序号改为连续序号。

### 探索发现

- **列表元数据回填**：新增 `enrichDiscoverItems` —— 只挑缺字段的条目，每页最多 **12 条**、并发 **3**，走 `loadComicDetail` 补 author/description/status，且回填发生在写发现缓存之前，下次命中缓存不再重复请求。浏览与搜索两条路径都接入。不物化封面，避免额外下载。
- 详情页在「共 N 章」右侧显示 `· 最后更新：YYYY-MM-DD`。

### 界面

- 本地仓库分页：`/api/local` 支持 `limit/offset` 并返回 `total`，首屏 60 条，滚动到距底部 400px 自动续页 + 「加载更多」按钮。
- 订阅卡片标题行重排：作品名占满剩余宽度，**内容源名 + 启停状态圆点（绿/红）贴在这一行最右端**。
- 三点菜单方向自适应：上方空间 > 260px 向上弹，否则向下。
- 禁用卡片灰度放宽为 `opacity .82 + grayscale .55`（悬浮 `.92`）；本地仓库章数胶囊背景改 `#f26a12`；滚动条悬浮高亮改品牌橘色。
- 系统设置：TG 与下载设置同排（三行为「账号+代理 / 下载设置+TG / 归档+关于」）；关于卡片放大并加橘猫 logo 水印。
- 已移除多选胶囊条与三点菜单里的启用/禁用（保留卡片右上角内容源图标点击启停）。

### 语义修正

- 作品详情页「只下载」不再隐式写入订阅；直接下载会创建 `temporary` 订阅卡片，任务跑完自动移除并保留已下载文件。
- 删除订阅卡片只取消/删除还在下载与排队中的任务，已下载文件与完成记录不动。
- 订阅清单排序改为 `created_at ASC`（按订阅先后）；任务列表同状态内按 `id ASC`（先入先出，与执行顺序一致）。

## 已知问题

- TG `sendPhoto` 用封面 URL 交给 Telegram 抓取，源站防盗链时会退回纯文本详情。
- 探索发现回填会让**首次**打开某一页多 3 条并发详情请求（最多 12 次），缓存命中后无额外开销；嫌慢可把 `discoverEnrichLimit` 调到 6、并发降到 2。
- `/api/discover/cover` 尚未接 `?w=`，命中 `cachedCover` 时仍按原图下发。
- 重复执行全量/补全不会产生重复任务（`CreateDownloadJob` 按 source+comic+chapter upsert）；若插件源两次返回的章节 ID 不同，仍会被视为两章。
